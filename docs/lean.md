# SetLaH In Lean 4

The Lean library supports constructing SetLaH programs, supplying facts in
memory, compiling to ASP, and solving through the canonical Python engine. It
targets Lean 4.32.0.

## Installation

Install Python 3.11 or later and SetLaH first:

```bash
python -m pip install .
setlah --version
```

Install Lean through `elan`, then verify this repository:

```bash
lake build SetLah
lake exe setlahDoctor
```

The client finds `setlah` through `PATH`. Set `SETLAH_EXE` to an absolute
executable path when the command is installed elsewhere:

```bash
SETLAH_EXE=/opt/setlah/bin/setlah lake exe setlahDoctor
```

To consume SetLaH from another Lake package, add a Git dependency and import the
facade module:

```lean
require setlah from git
  "https://github.com/yangdinglou/setlah.git" @ "lean4-binding"
```

```lean
import SetLah
```

Pin a release tag or commit instead of the branch once a compatible release is
available.

## Checked Quotation

`setlah%` parses embedded source during Lean elaboration, so malformed models
fail the Lean build at the quotation site:

```lean
import SetLah

open SetLah

def choice : Program := setlah% r#"
ExtDOM Item: INT.
ExtPred available: (Item).
[
  selected(X)? :- available(X).
  (\exists X. selected(X)).
]
"#
```

The Lean parser provides early syntax validation. The Python engine remains the
authority for semantic checking, rewriting, and ASP generation.

## Combinators

Programs generated by Lean code can use `SetLah.DSL`:

```lean
open SetLah.DSL

def choiceDsl : Program :=
  program
    [extDom "Item", extPred "available" [ty "Item"]]
    [block [
      choice (atom "selected" [v "X"]) [atom "available" [v "X"]],
      constraint (ex "X" (atom "selected" [v "X"]))
    ]]
```

## Instances And Facts

An `Instance` pairs a program with zero or more in-memory ASP fact sources.
Typed helpers cover common integer, string, function, atom, and constant facts;
`addRawFacts` is available for ranges and arbitrary Clingo input.

```lean
open SetLah

def instance : Instance :=
  (Instance.ofProgram choice)
    |>.addFact "dom_Item" [.number 1]
    |>.addFact "available" [.number 1]
    |>.addAtom { name := "available", arguments := [.number 2] }
    |>.addConst "limit" 2
    |>.addRawFacts "available(3..5)."
```

No temporary files are created. Independent calls can run concurrently without
sharing mutable filenames.

## Compile And Solve

The non-throwing functions return structured errors:

```lean
def run : IO Unit := do
  match ← solve instance with
  | .error error => IO.eprintln s!"{error.category}: {error.message}"
  | .ok result =>
      IO.println s!"status: {repr result.status}"
      for model in result.models do
        for selected in model.atomsNamed "selected" do
          IO.println selected.toAsp
```

`compile!` and `solve!` convert backend errors to `IO.userError` for concise
applications. Compilation returns generated ASP; solving returns
`satisfiable`, `unsatisfiable`, or `unknown` and structurally decoded models.

```lean
let compiled ← compile! instance { grounding := true }
IO.println compiled.asp

let solved ← solve! instance {
  grounding := true
  costConversion := true
  maxModels := 1
}
```

`maxModels` defaults to one. Use `0` only when all models are required. Extra
Clingo arguments can be passed with `clingoArguments`. Compilation also supports
`entailmentElim` (`"asp"`, `"egg"`, `"both"`, or `"none"`) and `verbose`.

## Engine Configuration And Errors

Pass `EngineConfig` to use a specific executable for one call:

```lean
let config : EngineConfig := { executable := some "/opt/setlah/bin/setlah" }
let result ← solve instance {} config
```

`BackendError.category` distinguishes unavailable engines, protocol failures,
parsing, semantic checking, compilation, grounding, and solving. The client
rejects incompatible protocol versions and invalid JSON instead of falling back
to another compiler.

Run `lake exe setlahDoctor` to check executable discovery, protocol
compatibility, Clingo availability, and a trivial SAT solve. Run
`lake exe setlahExamples` for the complete end-to-end example suite.

## Current Scope

The binding launches one subprocess per request for simple isolation. It does
not yet support cancellation, streaming models, optimization-specific results,
or incremental grounding. QCLS is excluded because it requires a richer Clingo
control and grounding API.
